20 元中移铁通插排（SY7T609）脱离 Home Assistant，使用 Windows 本地 ESPHome 更换 Wi‑Fi 与 OTA 刷机

20 元中移铁通插排（SY7T609）：脱离 Home Assistant，使用 Windows 本地 ESPHome 更换 Wi‑Fi 与 OTA 刷机

手里这只中移铁通插排已经刷入 ESPHome，计量部分使用 SY7T609 方案。它平时工作正常，但更换路由器后遇到了一个麻烦：旧固件没有开放网页配网，也没有可用的备用热点，插排无法直接填写新的 Wi‑Fi 名称和密码。

最常见的处理方式是在 Home Assistant 中安装 ESPHome Device Builder，然后重新编译并上传固件。但在部分网络环境下，Home Assistant 拉取插件镜像可能长时间停滞，甚至出现类似错误：

与其继续排查 Home Assistant 的容器网络，不如直接在 Windows 中安装 ESPHome。只要插排当前还能连接到旧网络，并且旧固件保留了 OTA 功能，就可以在电脑上完成配置修改、固件编译和无线上传。

本文记录完整操作过程。

[!IMPORTANT]
本文讨论的是 ESPHome 固件的 OTA 更新，不是给普通插排升级官方固件。

操作前必须确认设备已经刷入 ESPHome，并保留 OTA 组件。若 OTA 已被删除、OTA 密码未知，或者设备完全无法连接任何已知网络，就不能使用本文的无线方法，只能拆机后通过 3.3V USB 转 TTL 串口重新烧录。

一、先判断能不能使用 OTA 方法

开始前，先确认以下条件。

可以使用本文方法的情况

满足以下条件即可继续：

  • 插排已经运行 ESPHome；
  • 手里有该插排对应的 YAML 配置文件；
  • 旧固件中保留了 ota: 配置；
  • 知道旧固件的 OTA 密码，或者旧固件没有设置 OTA 密码；
  • 插排还能连接旧路由器，或记得旧 Wi‑Fi 的名称和密码；
  • Windows 电脑能与插排处于同一个局域网。

不能直接使用 OTA 的情况

出现以下任一情况，通常需要串口线刷：

  • 旧固件删除了 OTA 组件；
  • OTA 密码已经忘记；
  • 旧 Wi‑Fi 的名称或密码已经忘记；
  • 插排始终无法连接网络；
  • YAML 中修改了错误的芯片型号、闪存参数或关键引脚；
  • 无线上传过程中设备损坏且无法重新联网。

[!WARNING]
插排内部直接连接市电，拆机后存在触电风险。

进行串口刷机前必须完全拔掉市电，并确认高压电容已经放电。USB 转 TTL 必须使用 3.3V 电平，不要使用 5V 信号，也不要同时接入市电和串口供电。

二、需要准备的文件和工具

硬件

  • 已刷入 ESPHome 的中移铁通插排；
  • Windows 10 或 Windows 11 电脑；
  • 可用的旧路由器，或者支持移动热点的 Windows 电脑；
  • 新路由器的 2.4GHz Wi‑Fi 名称和密码。

ESP8266 只支持 2.4GHz Wi‑Fi。新路由器如果只开启 5GHz，插排将无法连接。

软件和文件

  • Python；
  • ESPHome；
  • 插排原始 YAML 配置文件；
  • 与配置文件匹配的 secrets.yaml；
  • 可选：文本编辑器，例如 VS Code、Notepad++ 或 Windows 记事本。

最关键的是原始 YAML 文件。它通常包含：

  • ESP8266 板型；
  • 继电器引脚；
  • 按键引脚；
  • 状态灯引脚；
  • SY7T609 计量芯片配置；
  • 功率、电压、电流传感器；
  • Wi‑Fi、API 和 OTA 设置。

不要为了换 Wi‑Fi 重写整份配置。 最稳妥的做法是保留原来的硬件定义，只修改 Wi‑Fi、OTA 和临时上传地址。

2. API 与 OTA 不是同一功能

这两个组件用途不同：

  • api:：供 Home Assistant 与 ESPHome 设备通信；
  • ota:：供 ESPHome 上传新固件。

即使删除 API 密码，OTA 密码也不会自动删除。

同样，Home Assistant 无法连接 API，并不代表 OTA 一定失效。

3. 不建议为了节省内存直接删除全部恢复通道

ESP8266 内存有限，删除 web_server 确实可以降低资源占用。但为了以后更换网络方便，可以考虑保留一个受密码保护的备用热点：

十四、让插排连接新路由器

OTA 完成后，插排会自动重启。

此时新固件中已经写入新的：

接下来的操作顺序：

  1. 开启新路由器的 2.4GHz Wi‑Fi；
  2. 确认 SSID 和密码与 secrets.yaml 完全一致；
  3. 等待插排重启；
  4. 在新路由器 DHCP 列表中查找插排；
  5. 记录新的 IP 地址。

如果新路由器把 2.4GHz 和 5GHz 合并为同一名称，通常也可以连接，但部分路由器的智能漫游、WPA3 或特殊加密设置可能导致 ESP8266 连接失败。

遇到问题时可尝试：

  • 单独开启 2.4GHz；
  • 使用 WPA2-PSK；
  • 暂时关闭 WPA3-only；
  • 暂时关闭 Wi‑Fi 6 专用模式；
  • SSID 不使用生僻字符；
  • 检查是否启用了 AP 隔离或 MAC 地址过滤。

3. 找不到插排 IP

依次检查：

  • 插排是否通电；
  • 旧 SSID 和密码是否完全正确；
  • 热点是否为 2.4GHz；
  • 电脑和插排是否在同一网络；
  • 路由器 DHCP 列表；
  • Windows 移动热点已连接设备；
  • arp -a；
  • ping 设备名.local。

4. OTA 连接超时

可能原因：

  • IP 写错；
  • use_address 指向旧地址；
  • Windows 防火墙拦截；
  • 插排和电脑不在同一子网；
  • AP 隔离阻止设备互访；
  • 旧固件没有 OTA；
  • OTA 密码不正确；
  • 设备正在不断重启。

5. 显示认证失败

通常是 OTA 密码错误。

OTA 验证使用的是旧固件当前保存的 OTA 密码。即使新 YAML 中填写了新密码，本次上传时仍必须先通过旧密码认证。

更稳妥的做法是：

  1. 第一次迁移 Wi‑Fi 时保持 OTA 密码不变；
  2. 确认新网络工作正常；
  3. 再单独修改 OTA 密码并进行第二次上传。

6. 编译成功但上传后无法联网

检查：

  • 新 Wi‑Fi 是否为 2.4GHz；
  • SSID 和密码是否有错；
  • YAML 是否引用了正确的 secrets；
  • 新路由器是否只允许 WPA3；
  • 是否开启 MAC 白名单；
  • 是否设置了不正确的静态 IP；
  • 网关、子网掩码和 DNS 是否正确。

如果仍保留旧网络，可以临时恢复旧热点，让设备重新上线后再次修改。

7. 插排在 Home Assistant 中离线，但 OTA 正常

说明 Wi‑Fi 和 OTA 可能正常，问题集中在 API。

检查：

是否存在，以及密码或加密密钥是否与 Home Assistant 一致。

8. 功率、电压或电流数值异常

不要随意修改 SY7T609 的 UART、引脚和校准参数。

如果只是换 Wi‑Fi，应保留原来的计量配置。数值异常时优先恢复原始 YAML 对比。

二十二、总结

中移铁通 SY7T609 插排更换 Wi‑Fi 的难点，不在于重新编译固件，而在于如何让旧固件保持在线，并建立一次可用的 OTA 通道。

真正需要注意的是：

  • use_address 只用于本次迁移；
  • 第一次迁移不要同时修改 OTA 密码；
  • API 与 OTA 是两套不同功能；
  • 清华 PyPI 镜像不等于所有编译依赖都走国内镜像；
  • 无法 OTA 时才考虑拆机串口刷写；
  • 串口操作必须断开市电并使用 3.3V 电平；
  • 公开配置前必须清除全部真实密码和密钥。

完成迁移后，记得删除临时地址、固定新 IP，并备份最终可用的 YAML 配置。下一次再更换路由器时，就不需要重新经历整套排查过程了。
